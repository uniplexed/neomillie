Neo Geo memory architecture: MiSTer and Analogue Pocket

Who shares a chip with the 68K

The two cores put the 68K's code on CRAM0 either way. What differs is who else reads that chip, and that decides how often the 68K waits. The figures are from the 68K wait counter on hardware, one play each: Metal Slug X, first mission, on the cart core, and Metal Slug on the CD core.

The Z80 is the part the cart core cannot copy from the CD core: a Neo Geo CD's sound program is 64 KB of RAM, which fits in M10K, while a cartridge's is a ROM of up to 512 KB. The cart core keeps the first part of it, and of the fix, in the SRAM, and caches what stays on CRAM0, so the 68K finds that chip free. After a load a copy engine fills the SRAM, about 46 ms, with the core held in reset.

How we designed the Pocket layout

Start from MiSTer, change the chips, not the logic

The video, sound and CD logic are MiSTer's. pocket_mem_mux.sv is a port of sdram_mux.sv and the client side of ddram.sv onto four chips. The CD transfer remaps are the ones of sdram_mux.sv with the target chip changed, so the cores keep MiSTer's behaviour and its bugs stay comparable.

Put each stream on the chip that suits it

  • Sprites to SDRAM. The sprite fetch is the heaviest stream: 64 bits each PCK1. The SDRAM's bursts serve it; it holds the 64 MB C ROM, or the CD's 4 MB SPR RAM.
  • 68K code and data to CRAM0. P ROM, BIOS, fix and M1 are short random reads, which an asynchronous PSRAM answers with a fixed latency. The 68K's wait counter measures what it costs.
  • Sound to CRAM1. ADPCM-A and -B read the V ROMs, or the CD's PCM RAM, on their own chip, with no 68K or sprite traffic to wait behind. On MiSTer these go to DDR3.
  • Fix and Z80 program to SRAM, as far as it holds. The fix layer is read every PCK2 and must not wait. In the CD core the SRAM is FIX RAM with its own arbiter; in the cart core it holds copies of the S ROM and the first part of the M1 ROM, made after each load, and what stays on CRAM0 goes through two small read caches.

One registered master per chip

Each chip has a fixed priority. CRAM0, cart: loader, save path, posted backup write, 68K, fix, Z80, S and M1 copy; CD: loader, 68K, CD write queue. CRAM1: loader > CD write > ADPCM-A > ADPCM-B. SDRAM: sprite > CD read > loader > CD write, with refresh spaced by a watchdog. SRAM, cart: fix, copy write, Z80; CD: fix > CD read > CD write. Requests stay pending until served. CD writes are posted to a queue, and PCM and FIX writes hold the 68K's DTACK until they reach the chip.

Owner's decisions for the CD core

  • Z80 RAM in M10K, as MiSTer: 64 blocks.
  • PROG RAM in CRAM0, its cost checked with the 68K wait counter.

What the Pocket cannot hold, and what it gains

  • C ROM up to 64 MB (MiSTer up to 128 MB with two SDRAM modules); V ROMs up to 16 MB (MiSTer's DDR3 has room for more); P ROM up to 8 MB plus a 1 MB PROG1.
  • No ARM: CD sectors come from the host over the APF bridge, a random read costing up to about 90 ms. cd_fetch keeps a 4-sector bank, prefetches the next three, and reads a seek's target while the drive seeks.
  • M10K is the tight resource: 281 of 292 in the CD release. The LC8951's real buffer (a ring of 16 KB or more, instead of the 2-sector cache) needs about 16 more blocks; moving the memory card to external memory is the planned way to find them.
